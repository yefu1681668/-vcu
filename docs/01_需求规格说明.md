# VCU 整车控制器需求规格说明（SRS）

版本 v1.2 | 2026-11 | 基于 ISO 26262 功能安全思路的 V 模型开发

## 1. 系统概述

整车控制器（VCU, Vehicle Control Unit）是新能源汽车的顶层控制节点，负责协调
BMS（电池管理）、MCU（电机控制）、TCU（整车输入）三大节点，实现上下电管理、
驱动扭矩控制、制动能量回收与故障诊断。

本项目采用基于模型开发（MBD）流程：

```
需求分析(SRS) → 架构设计(SDD) → Simulink/Stateflow 建模
   → MIL 测试(Python 参考实现) → 代码生成 → SIL/HIL 测试(CANoe CAPL)
```

## 2. 功能需求

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-01 | 上电自检 | Key ON 后 100 ms 内完成自检，无故障进入 PRECHARGE |
| FR-02 | 预充握手 | 母线电压 ≥ 电池电压 95% 并保持 100 ms 才置 READY |
| FR-03 | 预充失败保护 | 5 s 未完成预充进入 FAULT，报 0x0010 |
| FR-04 | 驱动扭矩 | D/R 挡且踏板 > 10% 时输出扭矩，按 PEDAL_TORQUE_MAP 插值 |
| FR-05 | 挡位限制 | P/N 挡扭矩输出为 0 |
| FR-06 | 驾驶模式 | ECO ×0.7 / NORMAL ×1.0 / SPORT ×1.15 |
| FR-07 | 能量回收 | 制动 > 5% 进入 REGEN，输出负扭矩，最大 300 Nm |
| FR-08 | 回收禁用 | SOC ≥ 95% 时禁止能量回收 |
| FR-09 | SOC 限扭 | SOC < 15% 触发 LIMIT_TORQUE，扭矩 ×0.5 |
| FR-10 | SOC 迟滞 | 15% 锁存、20% 恢复，防止阈值抖动 |
| FR-11 | 通信监控 | BMS/MCU 报文 500 ms 未收到判定通信丢失 |
| FR-12 | 故障停车 | 通信丢失 → STOP 故障，扭矩归零 |
| FR-13 | 故障恢复 | 通信恢复且 Key ON，回 INIT 重新预充 |

## 3. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-01 | 控制周期 10 ms（与 VCU_Status / TorqueCmd 报文周期一致） |
| NFR-02 | CAN 总线 500 kbps，符合 DBC 通信矩阵 |
| NFR-03 | 安全相关报文周期 ≤ 20 ms |
| NFR-04 | 所有输入信号做范围检查，越界按安全值处理 |
| NFR-05 | 故障状态具备可追溯故障码（16 bit） |
